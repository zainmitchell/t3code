# Dependency and migration manifest

The only supported series base is `5f64c5eb299a23d278ef043c416bd4dc801bc53c`, official nightly 3669. Use the complete four-part series or complete source archive. Only the final source is installable; module patches are not separate supported installations. Its new public commits begin at the public base. Private development commits are not part of its ancestry.

| Order | Component                         | Boundary                                                                                                                                                                                        |
| ----- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1     | Native messaging modules          | Peer links, forwarding modules and environment CLI.                                                                                                                                             |
| 2     | Native command-job/tick modules   | Host command-job runner, receipts and writer fence.                                                                                                                                             |
| 3     | Native factory modules            | Factory services, stages, tracker/integration logic, containment modules and dedicated client/MCP components.                                                                                   |
| 4     | Shared native runtime integration | Shared contracts, orchestration/launch/Stop hooks, registrations, scheduled-task integration, client state, dependency exports/patches and guides. This explicitly couples the earlier modules. |

The release's `PATCH-SERIES.json` names the exact parent/commit/tree and patch hash for each component. Apply in that order and build only the final revision. The series separates review artifacts without pretending that the shared runtime wiring is an independently installable feature.

`source-manifest.json` records every changed source path and hash. The patch includes the following dependency closure.

Use Node 26.12.1 and the pinned pnpm 12.14.0/Vite+ 1.4.0 toolchain. Effect and its platform/testing packages remain locked to 4.0.5. `@muse-code/sdk` remains 1.4.6; its patch adds process-spawn observation alongside existing process-exit observation. The patch and its lockfile entry must move together.

Use a new T3 home for evaluation. This preview does not offer an in-place upgrade from an existing official 3669 database: its effective IDs 68 and 69 name different migrations. The migrator rejects histories that would skip required schema through such a collision. Do not point an older build at a migrated preview database or infer compatibility from the largest migration number. Preserve any old environment independently.

There are no shipped project policies, factory configurations, accounts, tracker repositories, provider credentials or deployment scripts. The generic fixture policy is test input, not an operational policy recommendation. The deployment-shaped legacy retirement receipt parser and its tests were omitted. The generic native transfer and owner recovery paths remain.

The PR catalog distinguishes necessary capability lineage from optional work and history. It is not a PR-head cherry-pick sequence. Local factory evaluation does not require configuring peer links. Wider remote UI, delegation, import/export and handoff proposals remain optional context.

The current source also includes preparation-attempt failure identities and abandoned-branch cleanup, propagation of receipt-read failures, mobile refusal messages, reopened-item display and exact-head review-change routing. These require the matching Git workflow service, launch/management services, tracker review reader, factory stages and destination-permission fixtures. There are no additional migrations or dependency-version changes for those fixes. Their behavior is distinct from the still-unmerged current linked-environment PR heads.
